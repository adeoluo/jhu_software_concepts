Approach:
This project follows the assignment requirements by building a public-data scraping workflow for GradCafe that uses urllib to manage URLs, BeautifulSoup to parse HTML, and a defensive fallback strategy for dynamically rendered pages. The workflow is intentionally polite and checks robots.txt before collecting any data. The scraper stores raw text and normalized values to preserve traceability while allowing downstream analysis.

The project also includes a local LLM standardization pipeline by copying the provided llm_hosting starter files into the repository. The cleaning layer is designed to preserve the original program text while creating cleaned program and university fields for downstream usage. The code is structured around the required functions and helper methods so that scraping, cleaning, saving, and loading remain easy to maintain.

The project is intentionally organized so that Module 2 exists at the repository root, separate from Module 1, which is not modified in this work.

Known Bugs:
- The scraper is built to the project specification and is designed for a real GradCafe run, but the full 100k-record dataset must be generated by running the scripts in a live environment.
- Some site layouts may vary across pages and dates, so page-specific selectors may need small adjustments if the GradCafe structure changes.
- The local LLM standardization step depends on the provided llm_hosting setup and the model download behavior of the local environment.

Robots.txt compliance:
Before scraping, the scraper checks the public robots.txt file for the target site and avoids any pages or paths that are disallowed. The workflow is limited to publicly accessible pages and avoids bypassing login restrictions, CAPTCHAs, or rate limits. A screenshot or concrete robots.txt evidence will be captured during the live run and stored alongside the project materials before final submission.
